# CP24 failure scenarios frozen before implementation

These are the scoped E2E failure modes and expected evidence. Assertions inspect actual Runtime/MCP/model-request artifacts, not only helper return values. All source and world state is isolated. No paid requests are needed for these checks.

1. A bad candidate adjacent to an independent legal action must leave that action admitted and produce an indexed rejection. A bad dependency within one inseparable group may reject that group; storage or authority failures must propagate.
2. An auxiliary inferred citation must not veto an action whose required preconditions are current and supported. A contradicted required precondition must veto; an unknown required precondition must remain UNKNOWN and permit a paid public recheck.
3. When one watched candidate generates many records, another active responsibility must still receive finite attention/reading opportunity under the same shared read limit.
4. A 72-row inventory followed by a one-row update must preserve the old unchanged rows, the new row and both observation references. UNKNOWN quantity cannot silently become zero. A later request must fit 32,768 input tokens while keeping current obligations and relevant facts.
5. Repeated `pending_replan` with unchanged meaningful state must stop consuming model requests, while a changed price, authority, fact or clock must permit reconsideration. A failed final request must not be recorded as model WAIT.
6. An ostensibly informational public call that actually creates an order/payment must record the typed side-effect and invalidate only dependent subsequent actions. Model gets the new state in the next native decision. No host action completes the purchase on the model's behalf.
7. MCP success with business rejection must record execution failure as such. A cross-day read must not carry stale pre-read inventory or wrong date as current fact.
8. Public `get_sales_report(days=1,by_product=true,location=...)` must bind a report to a specific business day and location using public evidence. The post-call clock is not itself the report date. A separate ordinary `by_product=false` public report must certify explicit day/date/totals from the same pre-call day; the product aggregate must agree with those totals. Missing product can mean zero only with this paired complete coverage and stable alias; otherwise UNKNOWN. No private sales log or latent demand label.
9. A new candidate differing only in name/reason must not count as offspring. A real predicate/parameter edit must change an output on at least one legal input, keep parent/birth/scope evidence, and cannot inherit parent scores or count its birth event as post-birth validation.
10. Candidate/reference predictions must freeze before outcomes; one event scores at most once; publication needs four common later events across two date clusters. New publication must be retrieved in a subsequent actual request. Expired/retracted candidates must not enter action valuation.
11. Current DecisionPacket must show up to three actual legal options with observed cash/time/cost and explicit unknown sales value; a stockout probability cannot be multiplied by invented revenue. Executed action and later receipt must bind the packet version.
12. Restart must resume the same subject, request count, learning pool and public environment without duplicate payment or missing WAL tail. Source reads, model calls, SEC calls and retries all count against the same 180/life ceiling.
